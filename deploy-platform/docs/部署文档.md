# 发布部署平台 · 部署文档

## 环境要求

| 依赖 | 版本 | 说明 |
|------|------|------|
| Python | 3.10+ | 推荐 3.11/3.12/3.13 |
| Node.js | 18+ | 前端构建 |
| MySQL | 8.0 | 生产环境（开发默认 SQLite） |
| Redis | 7 | 缓存/流水线状态（可选，MVP 可不用） |

## 一、本地开发部署

### 1. 后端（Python + FastAPI）

```bash
cd backend

# Windows 用 py 启动器（本机 python3 指向 Store 重定向器，不可用）
py -m venv .venv

# 激活虚拟环境
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# 启动（首次自动建表 + 写入演示数据）
uvicorn app.main:app --reload --port 8080
```

> 默认使用 SQLite（`backend/deploy_platform.db`），无需额外安装数据库。
> 如已安装 MySQL，复制 `.env.example` 为 `.env`，修改 `DATABASE_URL`。

### 2. 前端（React + Vite）

```bash
cd frontend
npm install
npm run dev
```

访问 http://localhost:5173

### 3. 一键启动脚本

```bash
# Git Bash
bash scripts/start-backend.sh
bash scripts/start-frontend.sh

# Windows CMD
scripts\start-backend.bat
```

## 二、生产部署

### 后端（Docker）

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app ./app
EXPOSE 8080
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8080"]
```

### 环境变量（生产必配）

```bash
# 启动项（改了必须重启）
DATABASE_URL=mysql+pymysql://deploy:password@mysql:3306/deploy_platform?charset=utf8mb4
JWT_SECRET=<换成强随机密钥>
AES_KEY=<换成强随机密钥>
# 接口文档默认关。不要把 /docs 挂到 Nginx。本地开发脚本会开；内网需要时再设 API_DOCS_ENABLED=true
# Redis 可用环境变量覆盖平台设置，也可登录后在「平台设置」填写
REDIS_HOST=redis
REDIS_PORT=6379
```

大模型 Key、LDAP、企微、SMTP、ES 在「平台设置 / 模型配置」页配置，不要写进启动环境（除非要用环境变量覆盖同名项，如 ES_HOSTS）。

### docker-compose 示例

```yaml
services:
  backend:
    build: ./backend
    ports:
      - "8080:8080"
    environment:
      DATABASE_URL: ${DATABASE_URL:?set DATABASE_URL in .env}
    depends_on:
      - mysql

  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: password
      MYSQL_DATABASE: deploy_platform
      MYSQL_USER: deploy
      MYSQL_PASSWORD: password
    volumes:
      - mysql_data:/var/lib/mysql

  frontend:
    build: ./frontend
    ports:
      - "8000:80"

volumes:
  mysql_data:
```

## 三、基础设施部署（MySQL + Redis）

根目录 `docker-compose.yml` 已提供 MySQL 8 + Redis 7：

```bash
docker compose up -d
```

启动后：
- MySQL：`localhost:3306`，库 `deploy_platform`，root 密码 `root123`
- Redis：`localhost:6379`

后端切 MySQL（设环境变量 `DATABASE_URL`）：
```bash
DATABASE_URL=mysql+pymysql://root:root123@localhost:3306/deploy_platform?charset=utf8mb4
```

> 后端已有 `backend/Dockerfile`、前端已有 `frontend/Dockerfile` + `frontend/nginx.conf`，可完整容器化部署。

## 四、平台级配置（登录后在「平台设置」界面配置）

以下配置都放在「平台设置」页，无需改代码：

| 区块 | 用途 | 关键项 |
|------|------|--------|
| Redis 配置 | **定时触发器（cron）延迟队列** | host/port（默认 localhost:6379），不配则定时触发不生效 |
| LDAP 登录配置 | 含 @ 账号走 LDAP | 服务器地址、绑定账号、搜索基准、过滤器 `(mail={username})` |
| 企业微信登录配置 | 企微 OAuth2 | CorpId、AgentId、Secret、回调地址（须在可信域名内） |

> **定时触发**依赖 Redis 延迟队列：配好 Redis 后保存，流水线里的 cron 触发器才会真正定时执行（后台线程每 15s 扫描一次）。

## 六、换访问地址（加域名 / 换 IP / 上 HTTPS）

平台没有把访问地址写死在任何地方，但**已装的 Agent 是个例外**，换地址时要处理它们。

### 自动跟随，不用改

| 位置 | 为什么不用改 |
|------|-------------|
| 前端请求 | 请求路径是相对的（`/api/v1`），跟着浏览器地址栏走 |
| Agent 安装脚本 | 平台按**本次请求的地址**回填进脚本。用什么地址打开平台，脚本里就是什么地址 |
| 插件里的平台地址 | 由 Agent 在运行时注入，跟 Agent 的 `--server` 走 |
| 通知里的链接 | 站内信存的是相对路径，前端自己补域名 |

所以换域名后，在页面上重新复制一次安装命令，拿到的就是新地址。

### 必须处理：已装的 Agent

Agent 的平台地址是**装机时固化**在启动器里的，不会自己变：

| 系统 | 位置 |
|------|------|
| Windows | 安装目录下的 `start-agent.cmd` / `start-node.cmd`，`--server` 参数 |
| Linux（systemd） | `/etc/systemd/system/release-agent.service` 的 `ExecStart` |

**推荐做法：用新地址打开平台，复制安装命令，在每台机器上重跑一次。** 脚本会覆盖启动器并重启服务，比手工改文件可靠。

几个要点：

- **不会产生重复的机器记录**。注册是按机器名认的，同名会更新原记录，Agent 的 ID、token、权限、历史都保留。
- **需要接入凭证**。Agent 本地的登记凭据是按「平台地址 + 机器名」存的，地址一变就找不到旧凭据，会退回用接入凭证注册。重跑安装脚本时带上凭证即可（页面上的命令已经带了）。
- **过渡期让新旧地址都通**。先加好域名解析、让旧 IP 继续可用，再逐台切 Agent，切完再停旧地址。否则切换期间发布会失败。
- **节点（生产机）建议错峰切**。切的时候 Agent 会重启，此时若正在发布会中断。

### 上 HTTPS 时，外层反代必须传对两个头

平台靠请求头推断"我对外是什么地址"，再回填进安装脚本。外层反代（Nginx / F5 / 云 LB）做 HTTPS 卸载时要传：

```nginx
proxy_set_header Host              $host;      # 原始域名
proxy_set_header X-Forwarded-Proto $scheme;    # 这里是 https
```

漏了 `X-Forwarded-Proto`，安装脚本里会回填成 `http://域名`，Agent 连上去会被重定向或直接失败。

安装脚本**不采信** `X-Forwarded-Host`（客户端可伪造）。平台地址优先用「平台设置」里的 `public_app_base`；没配才用请求的 `Host`。

平台自带的前端 Nginx 已经处理了这一层：容器内只监听 80，宿主机映射 8000，会优先采信外层传来的协议，不会把 https 覆盖成 http。生产 compose **默认不把 MySQL 3306 / Redis 6379 映射到宿主机**，Redis 必须设 `REDIS_PASSWORD`。调试才用 `docker-compose.debug.yml`。

技能包（Markdown 说明）不强制签名。技能库上传会共享给全部人员；删除只有发布者或管理员。第三方流水线插件和工具含可执行代码，必须带 `manifest.sig`，公钥共用 `harness_tool_signing_keys`；上架和安装仅管理员。

### 检查是否生效

换完地址后，先确认脚本里回填的是不是新地址：

```bash
curl -s "https://新域名/api/v1/agents/install-script?role=builder" | grep RELEASE_SERVER
# 期望看到：$Server = 'https://新域名'
# 若看到 http:// 开头，说明外层反代没传 X-Forwarded-Proto
```

再到「构建机管理 / 节点管理」看各机器是否都在线。

## 七、常见问题

1. **`python3` 无输出/退出码 49**：本机 `python3` 指向 Windows Store 重定向器，请用 `py` 启动器或 `.venv` 内的 `python.exe`。
2. **bcrypt 报错 `__about__`**：本项目已改用原生 `bcrypt` 库，不再依赖 passlib，避免版本冲突。
3. **SQLite 锁表**：开发期并发写入少，一般无碍；生产请切换 MySQL。
4. **定时触发不生效**：先确认「平台设置 → Redis 配置」已配好且 Redis 可连通（否则调度线程降级跳过）。
5. **前端 build 报 `Cannot find module 'node:path'`**：缺 `@types/node`，执行 `npm install -D @types/node` 后再 build。
6. **虚拟机/局域网访问不到后端**：uvicorn 默认只绑 `127.0.0.1`，必须加 `--host 0.0.0.0`（启动脚本已内置）。验证：`netstat -ano | findstr :8080` 应显示 `0.0.0.0:8080`，而非 `127.0.0.1:8080`。
